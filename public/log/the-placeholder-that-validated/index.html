The placeholder that validated

A tool accepted the literal text YYYY-MM-DD as a date, signed it, and would have spent a press to find out. Three things this week that looked like they were working.

By William Shane Wilkinson · Salt Lake City · Approx. 5 minutes

Posting Thursday's log on Tuesday, because Thursday is a vendor fair and I will be in a room shaking hands rather than at a bench.

Three things this week, and they turned out to be the same thing three times: something that looked like it was working.

The placeholder that validated

I wrote a small tool that enrols a device — walks it through signing a challenge, then registers the result. It takes a manufacture date on the command line.

The first time I ran it against real hardware, I passed it the literal string `YYYY-MM-DD`. Not a date. The placeholder from the help text.

It accepted it. It signed it into the challenge. It printed it back out as the manufacture date, in the body of the record, with no complaint anywhere.

What saved me is that this was a dry run. A real run would have reached the device, spent an actual signature, and only then failed at the server with the date it should have rejected at the start. The signing element I use is rate-limited by design — I pace presses six seconds apart and treat each one as a thing I do not get back. Burning one to discover a typo is the specific cost I had designed the pacing to avoid.

The fix is dull and that is the point: parse the date, bound it to a range the company could plausibly have existed in, and refuse before the device is touched at all. `YYYY-MM-DD` is refused now. So are 2025-12-31 and 2030-01-01, both of which are perfectly well-formed dates and neither of which can be true.

Well-formed is not the same as correct, and this is the second time that exact sentence has cost me something. The first was an identity code: a placeholder written as `XXXX-XXXX-XXXX` passed the format check cleanly, because the character set the format uses happens to include X. The shape was valid. The thing it named did not exist.

A validator that only checks shape will wave through every placeholder you ever write, and placeholders are precisely the values most likely to reach production by accident.

The import that broke every device

A separate one, found the same week: a start-up call had been failing on every device of one family since a specific commit. The cause was a missing import — a helper that converts hex to bytes, referenced and never brought in.

Nothing subtle. It crashed, loudly, every time. Which raises the only interesting question: it had been broken for a while, so what was I running that never touched it? The honest answer is that my testing had drifted onto a path that did not exercise that call, and nothing told me, because a test you are not running does not report that it is not running.

The fix I did not build

The third one is the one I am most pleased about, and it involved writing no code.

A verification endpoint has been refusing every device that calls it. That is not a bug in the usual sense — a public page cannot safely hold the credential that call needs, so refusing is the correct behaviour. But the effect is a feature that does not work for anyone.

I drafted two fixes. Both worked by loosening the check.

Neither got built. The ruling was: do not weaken the thing that makes the record worth having in order to make a convenience work, and write down instead what a future product would need in order to do this properly — a credential issued per attempt, rather than one sitting in a page where anybody can read it.

So the endpoint still refuses, the copy that implied otherwise has been corrected, and the requirement is recorded for a product that does not exist yet. That is a worse week on paper than shipping the fix would have been. It is a better one for anyone who has to trust the result later.

The pattern

Three failures, one shape. A placeholder that passed its check, a call that nothing was calling, and a fix that would have worked by quietly lowering the bar.

None of them announced itself. The first two were found by running things against real hardware rather than against my expectations, and the third by asking what the fix actually cost rather than whether it worked.

Normal service resumes Thursday, from a conference hall.
